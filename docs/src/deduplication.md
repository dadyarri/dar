# Дедупликация

**dari** автоматически дедуплицирует файлы с одинаковым содержимым в пределах одного
архива. Это позволяет избежать повторного хранения байт данных при наличии копий.

## Принцип работы

1. Для каждого файла вычисляется хеш **BLAKE3** по оригинальному (до сжатия) содержимому.
2. `ArchiveBuilder` хранит словарь `checksum → data_offset` уже записанных файлов.
3. Если хеш нового файла совпадает с уже записанным:
   - Данные повторно **не записываются** в блок DATA.
   - В индекс добавляется новая запись, но поле `offset` указывает на блок данных
     первичной (оригинальной) записи.
   - В поле `bitflags` устанавливается бит `0x0001` (`INDEX_FLAG_LINKED_DATA`).

## Извлечение дедуплицированных файлов

При извлечении файла с флагом `INDEX_FLAG_LINKED_DATA` экстрактор находит первичную
запись с тем же хешем (без флага), читает данные по её смещению и распаковывает их.

Оба файла восстанавливаются с одинаковым содержимым.

## Дедупликация при append

Команда `append` загружает существующие записи архива (смещения и хеши) перед
обработкой новых файлов. Это позволяет дедуплицировать новые файлы как между собой,
так и по отношению к уже имеющимся в архиве.

## Дедупликация и шифрование

При шифровании nonce выводится детерминированно из BLAKE3-хеша файла. Это означает,
что дедуплицированные связанные записи могут использовать метаданные шифрования
(nonce, тег) из первичной записи без повторного шифрования.

## Ограничения

- Дедупликация работает только в пределах **одного архива**. Между разными архивами
  дедупликация не выполняется.
- Метаданные (имя файла, путь, права) **не дедуплицируются**: каждый файл имеет
  собственную запись в индексе.
